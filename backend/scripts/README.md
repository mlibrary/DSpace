# Backend maintenance scripts

These scripts prepare REST API credentials, remove empty DSpace bundles, and
clean up local credentials. Run the examples from the repository root.

| Script | Usage |
| --- | --- |
| `set-credentials` | Execute with the API URL to prepare credentials, then source the generated environment file. |
| `delete-empty-bundle` | Execute with a bundle UUID; dry-run by default, or pass `--delete`. |
| `unset-credentials` | Source in your current Bash or zsh shell to remove credential files and unset the exported variables. |

## Requirements

- Bash, `curl`, and `jq` on your `PATH`. `jq` reads and validates JSON responses.
- An existing, unexpired DSpace bearer token for the target environment.
- An account with permission to delete the target bundle when using `--delete`.
  Successful authentication or read access does not imply delete permission.

All scripts support `--help`. Copy only the commands, not terminal prompts or
HTTP response output.

## `set-credentials`

```bash
./backend/scripts/set-credentials https://your-backend.example.org/server/api
```

The argument must be an HTTPS REST API base URL ending in `/server/api`.
The script prompts for an existing bearer token without echoing it. You can
paste the token with or without the leading `Bearer ` prefix. This script does
not perform a username/password or SSO login; obtain the token separately.

The script calls `/authn/status`, verifies that the response confirms
authentication, and saves a curl cookie jar containing the
`DSPACE-XSRF-COOKIE`. It also captures the matching `DSPACE-XSRF-TOKEN` response
header. These matching values are required for mutating requests such as DELETE.

On success, it prints a command similar to:

```bash
source /private/tmp/dspace-credentials.EXAMPLE/credentials.env
```

Run the **actual command printed by the script** in the shell where you will run
the bundle script. The path above is only an illustration. Running the script
alone cannot change its parent shell's environment. Do not source
`set-credentials` itself.

The generated file exports:

| Variable | Purpose |
| --- | --- |
| `DSPACE_API_URL` | API base URL for the selected environment. |
| `DSPACE_TOKEN` | Bearer token without the `Bearer ` prefix. |
| `DSPACE_XSRF_TOKEN` | CSRF token sent in the `X-XSRF-TOKEN` request header. |
| `DSPACE_COOKIE_FILE` | Path to the matching curl cookie jar. |

Credentials are stored with private permissions in a temporary directory
outside the repository. Treat both the environment file and cookie jar as
secrets. Do not commit, share, or paste their contents into tickets or chat.

## `delete-empty-bundle`

### Dry run (default)

After loading the credentials, supply a **bundle UUID**, not an item or
bitstream UUID:

```bash
./backend/scripts/delete-empty-bundle 00000000-0000-0000-0000-000000000000
```

Replace the example UUID with the intended bundle's UUID. The script checks
whether the bundle exists, then checks its bitstream list. It reports whether
the bundle would be deleted without sending a DELETE request.

### Delete an empty bundle

Check the environment and review the dry-run result before adding `--delete`:

```bash
printf '%s\n' "$DSPACE_API_URL"
./backend/scripts/delete-empty-bundle --delete 00000000-0000-0000-0000-000000000000
```

| Bundle state | Default behavior | With `--delete` |
| --- | --- | --- |
| Not found (HTTP 404) | Report missing; no deletion. | Report missing; no deletion. |
| Exists and contains bitstreams | Report nonempty; no deletion. | Report nonempty; no deletion. |
| Exists and is empty | Report that it would be deleted. | Delete the bundle; require HTTP 204 to confirm success. |

Missing and nonempty bundles exit with status `0`. Invalid arguments, missing
configuration, request failures, and unexpected responses exit nonzero.

**Do not run deletion while another process could add bitstreams.** The
emptiness check and deletion are separate requests, not an atomic operation.
DSpace bundle deletion also removes its contents, including any bitstreams
added between those requests.

## Troubleshooting

- **Authentication is not confirmed or HTTP 401:** obtain a fresh token for
  the target environment and run `set-credentials` again.
- **DELETE returns HTTP 403:** verify authentication, matching CSRF cookies and
  header, and the account's permission to delete the bundle. Public GET
  requests may succeed even when authentication is invalid.
- **Cookie problems:** use the jar generated by `set-credentials`. A file
  containing only the CSRF token is not a curl cookie jar. Do not mix the
  token or cookie file from different credential-setup runs.
- **Variables are missing:** run the printed `source` command in the same shell
  where you invoke `delete-empty-bundle`.

## `unset-credentials`

When finished, source the cleanup script in the shell where you loaded the
credentials. It takes no arguments and requires `DSPACE_COOKIE_FILE` to still point
to the cookie jar created by `set-credentials`:

```bash
source backend/scripts/unset-credentials
```

It uses `DSPACE_COOKIE_FILE` to locate `cookies.txt` and the adjacent `credentials.env`,
removes those files and their generated directory, then unsets `DSPACE_API_URL`,
`DSPACE_TOKEN`, `DSPACE_XSRF_TOKEN`, and `DSPACE_COOKIE_FILE`. Source it rather than executing it:
a child process cannot unset variables in your current shell.

The script rejects unexpected paths and symbolic links. It removes only the
two credential files and uses `rmdir`, not recursive deletion. If unrelated
files prevent directory removal, it reports an error and leaves the environment
variables set so you can resolve the problem and retry. Missing credential
files are tolerated if the generated directory still exists.

Removing local files does not invalidate the bearer token on the server.
